# Sharing files between bots

While orders are excellent for sending commands and small, structured data payloads, they are not
suitable for transferring large files, datasets, or binary artifacts. For these scenarios, Botica
provides a built-in shared directory.

## How it works

Botica automatically creates a common Docker volume and mounts it at the `/shared` path inside every
bot container in the environment. This means that any file a bot writes to its `/shared` directory
is immediately accessible to all other bots at the same path.

This process is entirely transparent and requires no special configuration in your `environment.yml`
file. It works out-of-the-box for all bots in your environment.

## Usage examples

The following examples demonstrate a common pattern: one bot (Java) writes a report file, and
another bot (Node.js) reads it.

### Writing a file (Java)

This Java bot uses the `getSharedDirectory()` method to access the shared volume and writes a simple
text file to it.

```java
import es.us.isa.botica.bot.BaseBot;
import es.us.isa.botica.bot.ProactiveTask;
import java.io.File;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;

public class ReportGeneratorBot extends BaseBot {

  @ProactiveTask
  public void generateReport() {
    File sharedDir = getSharedDirectory();
    Path reportFile = sharedDir.toPath().resolve("daily-report.txt");
    String reportContent =
        "Report generated by " + getBotId() + " at " + System.currentTimeMillis();

    try {
      Files.writeString(reportFile, reportContent, StandardOpenOption.CREATE,
          StandardOpenOption.TRUNCATE_EXISTING);
      System.out.println("Successfully wrote report to: " + reportFile);
      // Publish an order to notify other bots that the report is ready
      publishOrder("report_notifications", "report_ready", reportFile.toString());
    } catch (IOException e) {
      System.err.println("Error writing to shared file: " + e.getMessage());
    }
  }
}
```

### Reading a file (Node.js)

This Node.js bot listens for a notification that the report is ready, then uses the
`SHARED_DIRECTORY` constant to read the content of the file written by the Java bot.

```ts
import botica, {SHARED_DIRECTORY} from "botica-lib-node";
import {promises as fs} from "fs";
import path from "path";

const bot = await botica();

// Listen for the notification from the generator bot
bot.on("report_ready", async (filePathPayload) => {
  try {
    // Although the payload contains the full path, we can construct it ourselves for safety
    const reportFile = path.join(SHARED_DIRECTORY, "daily-report.txt");

    console.log(`Reading report from: ${reportFile}`);
    const fileContent = await fs.readFile(reportFile, {encoding: 'utf8'});
    console.log(`Report content: "${fileContent}"`);

    // Process the report content...

  } catch (e) {
    console.error(`Error reading shared file: ${e.message}`);
  }
});

await bot.start();
```

## Common use cases

The shared directory is ideal for:

- **Passing large datasets:** Sharing CSV files, JSON logs, or database dumps between processing
  stages.
- **Generating reports:** A reporter bot can generate a PDF, HTML, or text report and save it for an
  archiver or notification bot to pick up.
- **Sharing binary artifacts:** Exchanging machine learning models, compiled assets, or other binary
  files.
- **Temporary storage:** Using the directory as a temporary scratchpad for multi-step processes
  where data is too large to pass through orders.
